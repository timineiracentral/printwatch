<objective>
Vertical slice "dashboard sumário em uma chamada": `GET /api/v1/stats/summary`.

Implementa o endpoint que alimenta os cards principais do dashboard (Fase 4 DASH-02: jobs/páginas hoje, top usuário/impressora do mês). Janelas temporais em calendário local (America/Sao_Paulo), top-N por **soma de páginas** do dataset agregado (D-20: KPI = volume real de papel/toner, não número de jobs).

Purpose: Reduz round-trips da Fase 4 — um único GET retorna tudo que os cards precisam. Reutiliza `_build_aggregated_subquery` do Plano 03-03 para garantir consistência: o "total de páginas" do sumário bate com a soma das `pages` da lista paginada.

Output: `GET /api/v1/stats/summary` retorna JSON com 3 buckets (hoje, mes, total), cada um com `jobs`, `pages`, `top_users`, `top_printers`. Tempo de resposta < 200ms para 50k registros (4 queries indexadas + subquery agregada).
</objective>

    3. Função privada `_compute_bucket(db, date_from_utc, date_to_utc, top_n) -> StatsBucket`:
       - Se ambos bounds são None: subquery sem filtros de data (bucket "total").
       - Caso contrário: aplica filtros de data convertendo para JobFilters com date_from/date_to (mas as bounds aqui já estão em UTC datetime — usar método alternativo: passar filtros via parâmetro extra ao builder OU construir o where direto).
       
       **Implementação concreta:** criar um `JobFilters()` vazio e patch manual: chamar `_build_aggregated_subquery(filters)` e depois aplicar `.where(PrintJob.timestamp >= ...).where(PrintJob.timestamp <= ...)` ao próprio statement antes do GROUP BY — para isso, o builder de jobs_service deve ser estendido com parâmetros opcionais OU aqui replicar a chamada minimamente.

       **Decisão pragmática:** o builder em jobs_service.py aceita `JobFilters` puro. Para stats, criar filtros sintéticos:
       ```python
       # Converter datetime UTC bounds para date local SP (D-20 — semântica é "dia local")
       date_from_local = date_from_utc.astimezone(_TZ).date() if date_from_utc else None
       date_to_local = date_to_utc.astimezone(_TZ).date() if date_to_utc else None
       filters = JobFilters(date_from=date_from_local, date_to=date_to_local)
       agg = _build_aggregated_subquery(filters).subquery()
       ```
       - `jobs = db.execute(select(func.count()).select_from(agg)).scalar_one() or 0`
       - `pages = db.execute(select(func.coalesce(func.sum(agg.c.pages), 0))).scalar_one() or 0`
       - `top_users`: 
         ```python
         stmt = (select(agg.c.username.label("name"), func.sum(agg.c.pages).label("pages"))
                 .group_by(agg.c.username)
                 .order_by(func.sum(agg.c.pages).desc())
                 .limit(top_n))
         top_users = [TopEntry(name=r.name, pages=r.pages) for r in db.execute(stmt)]
         ```
       - `top_printers`: idem mas group_by `agg.c.printer`.
       - Retornar `StatsBucket(jobs=jobs, pages=pages, top_users=top_users, top_printers=top_printers)`.

    4. Função pública `compute_summary(db: Session, top_n: int = 5) -> StatsSummaryResponse`:
       - `today_start, today_end = _today_bounds_utc()`
       - `month_start, month_end = _month_bounds_utc()`
       - `hoje = _compute_bucket(db, today_start, today_end, top_n)`
       - `mes = _compute_bucket(db, month_start, month_end, top_n)`
       - `total = _compute_bucket(db, None, None, top_n)`
       - Retornar `StatsSummaryResponse(hoje=hoje, mes=mes, total=total)`.

    Logging opcional: tempo total da chamada (`logger.info("stats summary: %.0fms", elapsed)`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cliente HTTP → /api/v1/stats/summary | Param `top` validado em range 1..50; sem entrada string arbitrária. |
| stats_service ↔ jobs_service | Reuso de função privada `_build_aggregated_subquery` cria acoplamento controlado interno (não atravessa boundary de processo). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04-01 | DoS | compute_summary executa 4× a subquery agregada (hoje + mes + total + total acrescimo de top) | accept | Cada query reusa índices; para 50k registros < 200ms total. Cache opcional em v2. |
| T-03-04-02 | Information Disclosure | top_users expõe nomes AD para clientes da rede | accept | Mesma exposição já presente em /api/v1/jobs?username=...; consistente com D-28. |
| T-03-04-03 | Tampering | Manipulação de `?top` para `top=0` ou negativo | mitigate | Query validation `ge=1, le=50` no FastAPI bloqueia em 422 antes do service. |
| T-03-04-04 | Spoofing | Janela "hoje" pode ser controlada pelo timezone configurado em settings.api_timezone | accept | settings vem de env var no startup; operador é o único que muda. Documentado. |
</threat_model>
