# Phase 5.2: User–Printer Access Policy — Context

**Gathered:** 2026-05-27  
**Status:** Ready for planning

<domain>
## Phase Boundary

Política **permissiva** N:N usuário ↔ impressora: cadastro de impressoras permitidas e padrão por usuário, export de roteiro TI (CSV + imprimível), indicador read-only de conformidade na auditoria de jobs, e UX de onboarding de filas com terminologia operacional — **sem bloquear impressão**, **sem enforcement no CUPS**, **sem alterar watcher**.

**Cadeia alvo:** `user_printer_access` (SQLite) + API → Settings (ficha usuário = escrita; impressora = leitura) → export TI → flag `outside_policy` em jobs/API/export.

**Invariants (herdados + reforçados):**
- Política 100% observacional/auditável; nunca enforcement.
- Nenhuma regra de acesso bloqueia impressão física ou spooler.
- Watcher e pipeline append-only **desacoplados** de policies (sem SQLAlchemy org no watcher; sem hook CUPS).
- Sistema funciona integralmente com **zero** vínculos cadastrados.
- APIs de leitura rápida (list jobs, list printers) **não** dependem do container CUPS.

**Não inclui:** bloqueio CUPS / cotas (v2.5 POLICY), herança por departamento, portal self-service, auth dashboard, `discovered-queues` via lpstat.

</domain>

<decisions>
## Implementation Decisions

### A. Policy model (locked)

- **D-01:** N:N `user_printer_access` (`user_id`, `printer_id`, `is_active`, `is_default`); no máximo **um** `is_default=true` por usuário entre atribuições ativas.
- **D-02:** Modelo **permissivo** — usuário sem atribuição ou job em impressora fora da lista **não** bloqueia impressão; só orienta TI, export e relatórios.
- **D-03:** Uma fila por impressora no registry (1:1); escolha no cliente = Windows IPP; PrintWatch audita `printer_id` / fila usada.
- **D-04:** Política enriquece analytics/conformidade; **nunca** controla spooler nem `pre_process_job`.

### B. Onde editar atribuições (1C + refinamentos)

- **D-05:** **Fonte única de escrita** = ficha do usuário (Settings > Usuários) — multi-select de impressoras + marcação de padrão.
- **D-06:** Página da impressora = **somente leitura**: lista usuários com acesso + links/atalhos para abrir ficha do usuário correspondente.
- **D-07:** **Proibido** editar N:N na tela da impressora — evita estados divergentes entre telas.
- **D-08:** API primária: `PUT/PATCH` assignments via escopo usuário (`/api/v1/users/{id}/printer-access` ou equivalente); GET invertido em impressora é read-only.

### C. Limites e selector de impressoras (2A + refinamentos)

- **D-09:** Sem cap de negócio no banco — atribuições **ilimitadas** (validação técnica razoável apenas, ex. ≤50 ativas por request se necessário anti-abuse).
- **D-10:** UI deve permanecer utilizável com muitos vínculos: **multi-select pesquisável** com agrupamento por departamento e/ou localização da impressora.
- **D-11:** Ordenação no selector: impressoras **mais usadas recentemente** pelo usuário (via jobs) aparecem primeiro; depois demais ativas do registry.
- **D-12:** Aviso não bloqueante opcional na UI se >10 impressoras atribuídas (“revisar necessidade”) — não impede salvar.

### D. Export roteiro TI (3C + refinamentos)

- **D-13:** **Mesmo dataset** para CSV download e página imprimível (`GET /api/v1/users/{id}/ti-export` ou nome equivalente).
- **D-14:** Colunas/campos obrigatórios (uma linha por impressora atribuída ao usuário):
  - `display_name` (usuário)
  - `username` (`cups_username`)
  - `printer_display_name`
  - `cups_queue_name` (valor registry; label UI pode omitir “CUPS”)
  - `ipp_url` (derivado de IP/host do registry + fila)
  - `is_default` / “Impressora padrão”
  - `department` (do usuário)
  - `location` (da impressora, se cadastrada)
- **D-15:** Página imprimível = layout **extremamente simples** e operacional — título “Roteiro de instalação”, tabela legível, sem chrome do app; botão “Imprimir” / `window.print()`.
- **D-16:** CSV com header em PT-BR alinhado aos mesmos campos; UTF-8.

### E. Outside policy na auditoria (4C + refinamentos)

- **D-17:** Expor `outside_policy: boolean` na API de jobs (lista + detalhe) e no export CSV existente.
- **D-18:** UI Jobs: **badge discreto** (sem visual alarmista) + **filtro** “Fora da política” + **coluna opcional** (toggle ou ícone com tooltip — evitar tabela larga por padrão).
- **D-19:** Tooltip do badge: *“Usuário imprimiu em impressora não atribuída”*.
- **D-20:** Regra de cálculo — `outside_policy = true` **somente** quando:
  1. `username` resolve para `users` cadastrado e ativo (`is_active`), **e**
  2. `printer_id` não nulo (job mapeado a impressora registry), **e**
  3. impressora **não** está em `user_printer_access` ativo para esse usuário.
- **D-21:** **Não** marcar: usuário desconhecido/não cadastrado; `printer_id` nulo; impressora desconhecida; jobs órfãos/incompletos — evitar ruído operacional.
- **D-22:** Usuário cadastrado **sem nenhuma** atribuição → `outside_policy = false` (política permissiva; ausência de lista ≠ violação).

### F. Filas detectadas / terminologia (5A + refinamentos)

- **D-23:** Fase 5.2 usa **apenas** `GET /api/v1/printers/unmapped-queues` (filas no log sem cadastro no registry) — **sem** `discovered-queues` / lpstat.
- **D-24:** Princípio preservado: endpoints de leitura rápida **não** invocam container CUPS (manter `test_list_printers_does_not_call_cups` e equivalentes).
- **D-25:** Terminologia operacional consistente na UI principal:

  | Conceito | Label PT-BR |
  |----------|-------------|
  | Fila vista no histórico, sem registry | **Fila detectada** (picker cadastro) |
  | Fila com impressora cadastrada | **Fila mapeada** |
  | Estado antes do cadastro / banner onboarding | **Fila não cadastrada** |

- **D-26:** Remover/substituir jargão “CUPS” em labels primários (manter `cups_queue_name` apenas como campo técnico/API se necessário em tooltips ou colunas admin).
- **D-27:** Banner unmapped existente (D-13 Fase 5) atualizado para nova nomenclatura.

### G. Schema & technical

- **D-28:** Nova tabela `user_printer_access` via Alembic; índices em `user_id`, `printer_id`; unique `(user_id, printer_id)`.
- **D-29:** Constraint app-level: um `is_default` por usuário; ao marcar novo default, desmarcar anterior.
- **D-30:** Cálculo `outside_policy` em **read-time** na API (join users + user_printer_access) — **não** persistir coluna em `print_jobs`; **não** no watcher INSERT.
- **D-31:** `ipp_url` construído no backend a partir de `ip_address` + queue (padrão documentado no plano; ex. `ipp://{host}/printers/{queue}`).

### H. Invariants (non-negotiable)

- **D-32:** Falha em policy/export/UI **não** afeta watcher nem impressão.
- **D-33:** Watcher não importa modelos de `user_printer_access`.
- **D-34:** Zero vínculos cadastrados → sistema idêntico ao comportamento pós-Fase 5 (audit + registry).

### Folded Todos

</decisions>

<specifics>
## Specific Ideas

- Roteiro TI = documento que TI leva ao PC do usuário — minimalista, uma tabela, uma impressora por linha.
- Selector deve sentir-se “inteligente” com uso recente no topo — reduz fricção em reatribuição.
- Outside policy é ferramenta de **conformidade soft**, não alerta de segurança.
- Terminologia “Fila detectada / mapeada / não cadastrada” unifica onboarding e access policy na linguagem do admin TI.

</specifics>
