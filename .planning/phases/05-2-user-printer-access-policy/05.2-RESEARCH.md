**Documentação externa (Context7):**

- FastAPI — `APIRouter` aninhado: `users.router` + rotas `/{user_id}/printer-access` no mesmo módulo ou sub-router incluído **antes** de `/{user_id}` catch-all se ordem conflitar (rotas estáticas primeiro).

**Invariante herdado (Fase 5 D-29):** Falha em policy/export/settings **não** afeta watcher nem impressão física — distinto de 5.2-CONTEXT D-29 (um `is_default` por usuário).

## Schema

```text
user_printer_access (
  id INTEGER PK,
  user_id FK users NOT NULL,
  printer_id FK printers NOT NULL,
  is_active BOOLEAN NOT NULL DEFAULT 1,
  is_default BOOLEAN NOT NULL DEFAULT 0,
  created_at, updated_at,
  UNIQUE (user_id, printer_id)
)
INDEX idx_upa_user_id (user_id)
INDEX idx_upa_printer_id (printer_id)
```

**Regras app-level (5.2-CONTEXT D-29):**
- Ao `PUT` assignments: no máximo um `is_default=true` entre `is_active=true`.
- Desmarcar default anterior ao marcar novo.
- Soft-disable via `is_active=false` (não deletar linha se histórico importa — preferir soft como master data).

**`ipp_url` (D-31):** `ipp://{host}/printers/{queue}` onde `host` = `Printer.ip_address` se preenchido, senão hostname derivado de `cups_queue_name` **não** — exigir IP para export ou omitir URL com aviso no JSON. Plano: usar `ip_address` obrigatório para linhas no export; se null, `ipp_url: null` + campo `ipp_url_note: "Cadastre IP da impressora"`.

## API Design

| Method | Path | Behavior |
|--------|------|----------|
| GET | `/users/{id}/printer-access` | Lista assignments ativos (+ inativos se `include_inactive`) |
| PUT | `/users/{id}/printer-access` | **Replace** conjunto: body `{ assignments: [{ printer_id, is_default?, is_active? }] }` |
| GET | `/printers/{id}/users` | Read-only: users com acesso ativo |
| GET | `/users/{id}/ti-export` | JSON rows; `?format=csv` → `text/csv; charset=utf-8` |
| — | Jobs list/detail/export | Campo `outside_policy: bool` |

**PUT replace** evita drift entre UI única (ficha usuário) e API (D-05, D-08). PATCH por linha é opcional v2 — não no MVP 5.2.

**Validação PUT:**
- `printer_id` deve existir e `printers.is_active=true`
- Duplicatas no payload → 422
- Mais de um `is_default=true` → 422
- Lista vazia permitida (limpar todas — permissivo)

## outside_policy Algorithm (read-time)

Pré-computar por request (lista jobs):

1. Carregar mapa `cups_username.lower() → user_id` para `users.is_active=true`.
2. Carregar `user_id → set(printer_id)` de `user_printer_access` onde `is_active=true`.
3. Para cada job agregado:
   - Resolver `user_id` por `username` (case-insensitive match em `cups_username`).
   - Se `user_id` ausente → `outside_policy=false` (D-21).
   - Se `printer_id` ausente no job (agregação precisa `max(printer_id)`) → `outside_policy=false`.
   - Se usuário sem nenhuma atribuição ativa → `outside_policy=false` (D-22 permissivo).
   - Se `printer_id` ∉ set do usuário → `outside_policy=true`.

**Agregação:** Incluir `func.max(PrintJob.printer_id).label("printer_id")` em `_build_aggregated_query` — necessário para policy sem N+1.

**Filtro API:** `JobFilters.outside_policy: Optional[bool]` — quando `true`, filtrar pós-agregação ou subquery; SQLite: filtrar em Python após fetch se performance OK (<500 rows/page); se lento, materializar subquery com join.

## Performance Notes

- Lista jobs: batch load policy maps once per request (2 queries + 1 jobs query).
- TI export: 1 user + N assignments — trivial.
- PUT assignments: transaction única; delete+insert ou upsert por `printer_id`.
